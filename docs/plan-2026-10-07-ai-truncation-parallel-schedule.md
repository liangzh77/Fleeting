# Fleeting：模型截断自动处理、并行生成、每天 01:00 整理昨天

## 用户要求与边界

1. 点击 AI 整理报「模型输出截断，请缩小记录范围」：正常长度的随笔不应要求用户手工删减；自动缩小模型任务，保留原文、来源及既有生成内容。过长/服务商硬限制下仍无法完成时要诚实报错，绝不悄悄漏掉原文或保存不完整结果。
2. 正在生成当日整理时允许在洞察页面同时生成月度回顾（反之亦然）；同一 `kind+period` 不允许重复启动；任务失败不阻塞另一任务。
3. **每天按 `config.timezone` 的凌晨 01:00**，自动整理前一个日历日；无记录或未配置模型不调用模型；重启与重复 tick 不导致同一天重复调用；离线错过 01:00 时，当天 01:00 以后重启可补做昨天，但不追溯更久日期。自动触发来自用户本次明确授权，README 告知会向配置的模型服务发送昨天的私人原文；此前手动生成的用户同意弹窗保持不变。
4. 保留旧成功日/月结果直到新的成功产生；自动生成失败亦保留旧内容与原文。不要改变已有入口、录入、来源弹窗、补录、导出、登录/CSRF 与页面样式。测试不得用真实私有配置、数据库、真实模型或泄漏原文。

## 当前问题

- `src/ai.ts` 的 `call()` 固定 `max_tokens:8192`，遇到 `finish_reason='length'` 直接抛错；日任务按 12000 字分块，即使单条 8000 字也不拆，且每块日整理做两遍；月最终请求包含**全部原文**，长月材料也会触发截断。不能只增加一个 token 参数或截掉材料。
- `Ai.generate` 用 `SELECT ... WHERE state='running'` 全局互斥；`web/app.ts` 的全局 `generating` 布尔值也限制跨页面并发（并可能由旧页面回调改写当前状态）。
- `src/server.ts` 没有时区调度器。

## 设计/实现要求

### A. 输出截断

- 引入**有限次数、有限规模的自动拆分/重试**：日整理降低每个模型任务的输入预算；如果模型明确返回截断，自动把待处理 batch 拆半分别完成两阶段整理；单条记录过长时按有界文本片段拆，片段保留同一来源 ID、原文顺序与补录时间语义，最终每条原记录均被覆盖，分段来源仍可追溯完整原文。拆分必须在模型调用前或截断重试时生效，不得静默取前缀、截断 JSON、跳过材料、伪造来源。
- 月度：分类阶段也需针对长单条/批次做有界处理；最终聚合阶段不能再无限传全部原文和信息点而溢出输入/输出预算。设计层级归纳或有界证据/摘录步骤；输出证据 quote 仍须逐字属于对应完整原文（现有程序校验不能删除），ID 有效、覆盖全部记录的分类与程序统计口径不得退化。月报告在输入大时也能完成或明确报无法处理，不能靠砍掉一部分来源蒙混过关。
- 不盲目提高 `max_tokens` 超过服务商支持的上限；重试有停止条件，不无限发送模型请求。因重试失败旧结果仍可见。将错误文案改为准确告知已尝试自动拆分/重试且仍受模型限制，而非直接要求用户缩小记录范围。
- 添加模拟 `finish_reason='length'` 的自动拆分成功测试（日长单条 + 多条、月长材料或月最终聚合）、不可恢复时的有界失败测试，以及结构/证据/来源覆盖测试；验证确实处理完整原文而非只处理前半部分。

### B. 并行

- 后端将全局 running 限制改成**同一 kind+period** 的互斥（SQLite 同步登记任务，避免同时多次点击的竞争），允许 day 与 month 同时，也允许互不相同范围；原结果读取最新成功与最新任务的机制继续正确。
- 前端由全局 `generating` 改为按 `kind+period` 的任务状态；从随笔切到洞察时，正在运行的日整理不能阻止洞察生成，反向同理。各自按钮、轮询与消息只属于其范围，旧范围的异步响应/定时器不可覆盖当前范围（保持先前 reportScope/request 隔离）。同一范围并发不可重复启动，失败不影响另一个任务。
- 测试：可控 gate 的 day/month 同时在 running 状态；重复同范围被拒且不多建任务；释放/失败一个时另一个仍在运行且最终结果正确；浏览器切换两个页面启动、各自显示进度/最终内容，不覆盖草稿或别的范围。

### C. 每天 01:00 自动整理昨天

- 新建小型服务端调度模块，由 `src/server.ts` 在成功启动后初始化并在 SIGTERM/SIGINT 停止；使用 `Intl.DateTimeFormat` 配置时区判断**当地日历日和当地时刻**，昨天用日历日减一天（UTC 日期算法只用于 YYYY-MM-DD 日期运算，不能拿固定 24 小时减法求本地昨天）；兼顾不同服务器本地时区与 DST。定时检查即可（如每分钟），`unref` 定时器、停服务清理；启动时可检查当天 01:00 后的漏执行，绝不执行今天或更早于昨天的范围。
- 没有模型配置或昨天没记录直接跳过，不写失败任务；已存在相同指纹的成功结果无需重复生成。持久化“这一天自动尝试过昨天的某个范围”标识，先原子登记再调用；重启和每分钟重复 tick 不会重复提交。自动任务与手动同范围冲突时，不错误消费自动尝试机会；非同范围的月度任务允许与自动整理同时执行。
- 失败只保留失败状态/安全日志，不输出私人正文、模型原始返回或 API Key；本日不无限重试，用户仍可手动重试；下一个自然日仍会处理新一天。
- 测试使用可注入时钟与 mock Ai/fetch，覆盖 00:59 不调用、01:00/01:01 一次、昨天归档（包括月/年/闰日边界及非本机时区）、无模型/无记录、已有最新成功跳过、重启同日幂等、失败不重复、与手动同范围冲突/洞察并行、旧结果不清除。
- README 简洁注明服务需运行、配置时区、默认 01:00 自动发送昨天原文到模型、离线当日重启可补执行、未配置或无记录跳过，以及失败可手动重试。手动确认对话不移除。

## 验收与执行

- 必跑 `npm run typecheck`、`npm test`、`npm run build`、`npm run test:production`、`CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:browser`、`npm run format:check`；记录真实输出。允许增加测试或调整 mock，但必须保持原有回归。
- 独立验收需真实阅读代码并额外复核三类边界：截断后**全覆盖**与有界重试，前后端并发+跨页面异步隔离，01:00 时区/持久幂等/失败/重启。不可只凭执行方自述或现有通过的测试判定 approve。
- 在所有验收通过前不触碰私人数据库、不重启现有本地服务。验收通过后由主会话决定备份及部署，明确告知用户自动触发隐私影响与实时模型质量尚未实测。
