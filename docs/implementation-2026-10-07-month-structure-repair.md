# 月度结构修复：执行结果

## 改动

- `src/ai.ts`：软数组上限保留前 N 项，硬上限 2000 项仍失败；字段文本通过 `textBoundary` 截断，不切 UTF-16 代理对。洞察 4、changes/connections 6、questions 4、每片分类主题 5。quote 截断后仍校验对应资料的连续子串。
- 解析支持首尾 ``` / ```json 围栏。结构错误独立于 HTTP、网络、超时、调用预算和 `Truncated`；只把模型 content 的无效 JSON 归为可修复错误，服务响应外层损坏仍按网络/格式错误处理。
- 统一 `structured` 包装用于月分类、叶回顾、层级归纳/压缩、日第一阶段、日核对阶段。结构/来源/证据错误将该次模型输出、固定字段诊断、原任务资料和期望结构送回同一模型，最多修复一次。修复调用也受 512 调用 / 60000 材料字符上限约束。
- 顺序：每个逻辑步骤先调用/校验，结构错误最多一次修复；原调用或修复的 `Truncated` 交给原有拆分路径。层级归纳截断则压缩双方，再聚合；每个压缩/聚合步骤自身也最多一次结构修复。网络/HTTP/超时/超预算不修复、不转成结构错误。
- 月度证据校验限定为该步骤给定原文/摘录，不允许叶回顾引用其他批次，也不允许聚合引用未提供证据。多个同 ID 摘录逐个匹配。日第一阶段也必须通过分段和来源覆盖校验，之后才核对。
- 阶段/字段错误示例：`月度叶回顾结构校验失败：insights[0].question 为空`，不包含原文、模型正文、ID 或凭据。失败仍写新任务 failed，旧 ready 保留，UI 继续沿用 error 字段。
- `src/config.ts`：新增可选 reasoningEffort / extraBody；环境变量优先，空字符串可清除文件设置。extraBody 为 JSON 字符串，非对象/非法 JSON/超过 2000 字符/程序自有键冲突启动报错。请求合并顺序：程序字段 → reasoning_effort → extraBody；默认均不发送。服务商特有字段是否被支持不保证。
- `README.md`、`config.example.json`：默认推理行为、关闭推理示例、预算及裁剪策略。JSON 无注释语法，使用不发送的 `_reasoningExamples` 说明对象。
- 新增 `.prettierignore`：正式 format 命令排除真实私有配置与数据库，避免 glob `*.json` 读取 `config.local.json`。
- 新增 `tests/ai-structure.test.ts`、`tests/ai-structure-evidence.test.ts`，全部 mock / 合成资料。

## 空字段与缺证据策略

不填默认 limitation/question/overview，不将必填空白视为成功，不静默过滤无证据洞察。第一次错误进入一次结构修复；仅修复结果满足非空字段、合法来源、原文证据与数量要求才成功。修复仍错则整次失败并保留旧 ready。最后整月仍要求多记录至少两条洞察；分片叶回顾不会因单片不足两条而失败。
