# 月度“洞察”主题分类（2026-11-02）

## 背景

旧版“月度分类”提示词允许模型为每条记录自由生成 1–5 个“从内容涌现”的主题。2026-10 的结果有 10 条来源，却产生了 **47 个主题**，其中 **46 个只出现一次**，平均每条 4.8 个标签。图表变成很长的长尾列表，无法用来比较“这个月主要在关心什么”。

目标：无论一个月有多少条笔记、内容多分散，**图表中的不同主题数最多 10 个（含“其他”）**。

## 提示词（月度分类）

```text
按每条原文抽取信息点，并从下面固定的主题表中选择分类。输出 {"entries":[{"id":"ID","themes":["主题"],"gist":"一句话简介","points":"详细信息点（最多1000字）"}]}，每条一次。不要输出计数、解释、编号或主题层级。

主题表（只能使用以下名称，必须逐字照抄；不得改写、缩写、翻译、创造新主题或使用近义词）：
1. 工作与事业
2. AI与技术
3. 学习与思考
4. 家庭与亲子
5. 人际与沟通
6. 情绪与心理
7. 健康与身体
8. 生活与日常
9. 价值观与自我
10. 其他

主题范围与边界：
- 工作与事业：职业、项目、产品、创业、协作、工作安排、收入；以工作/项目本身为中心时使用。
- AI与技术：AI 使用与学习、技术、工具、自动化、软件、测试；以 AI/技术本身为中心时使用；AI 产品项目优先归“工作与事业”。
- 学习与思考：阅读、课程、学习方法、认知、方法论、复盘、观点整理；不包含具体工作项目。
- 家庭与亲子：孩子、伴侣、父母、家庭关系、教育、陪伴。
- 人际与沟通：朋友、同事、社交、冲突、表达、共情、边界；家庭关系归“家庭与亲子”。
- 情绪与心理：情绪、压力、焦虑、自我觉察、心理咨询、内在状态；不把具体事件本身归到这里。
- 健康与身体：运动、睡眠、饮食、疾病、就医、身体感受。
- 生活与日常：家务、居住、消费、假期、出行、日常安排、琐事。
- 价值观与自我：人生意义、选择、身份、成长、信念、价值判断；不包含具体情绪或家庭事件。
- 其他：确实无法归入以上任何一类时使用，尽量少用。

分类规则：
- 每条记录通常只给 1 个最主要的主题；只有内容确实同时围绕两个重要主题时，才给第 2 个。最多 2 个，禁止 3 个及以上，并按重要性排序（主要主题在前）。
- 按整条记录的中心意思归类，不要按单个词、单个人物、地点或一次事件拆成多个主题。
- 能归入更宽泛的主题时，不要使用更窄的说法；不要输出子主题、层级或解释。
- 同一主题在所有记录中必须使用完全相同的名称（包括措辞）。
- 如果想到的词不在主题表中，必须改选最接近的合法主题，不能发明新名称。
- “其他”只在确实无法归入 1–9 时使用。
- 每条记录都要给 gist：一句话概括这条记录在说什么，不超过40字；只概括，不评价、不建议、不添加原文没有的信息。
- 保留疑问、例子、限制、矛盾与观点；points 最多 1000 字；不要猜测频数。
```

## 提示词（月度回顾：建议与追问）

```text
生成月度回顾。事实与建议明确分离，不硬凑结论，缺材料在 overview 和 limitation 说明。通常 insights 为 2–4 条，只有一条原文时允许 0–2 条。changes 为观点变化的时间线（按日期排列，不把差异当成长），connections 为可能的主题联系；各自最多 6 条，证据不足可空。

建议要求：像一个不讨好你的专业顾问，基于第一性原理、证据和长期后果给建议。advice 是判断、取舍或下一步，不是安慰、夸奖、迎合或泛泛的可能性。优先指出我可能忽略的长期代价、结构性原因和可验证的下一步；直接说明最重要的问题、代价、风险和该做什么。在证据允许的范围内给出最有洞察、最有远见的判断，但不要为了深刻而过度推断。不要使用“你已经做得很好”“相信自己”“慢慢来”等安慰或鼓励套话，不要为了让我舒服而弱化问题，不要心理诊断，不要虚构原文没有的动机、情绪或经历。材料不足时明确写“材料不足，无法可靠建议”，不要硬给建议。advice 必须与 fact 分开，不能把建议写成原文事实；推断要标明是推断，不确定时说明。

limitation 写建议的适用条件、反例或缺失信息；question 写一个能检验或推进该建议的追问，不要泛泛提问。questions 是结合建议的追问：用于检验建议、补齐关键信息或决定下一步；每个问题都必须能追溯到上面某条建议；不要重复或近似重复，如果两个问题证据相同且实质相同就合并成一个。未记录答案不代表现实未解决。

证据 quote 是原文精确摘录。输出 {"overview":"阶段概括及局限","insights":[{"fact":"原文事实","advice":"给你的专业建议","limitation":"适用条件或局限","question":"结合建议的追问","evidence":[{"id":"ID","quote":"原文摘录"}]}],"changes":[同洞察结构],"connections":[同洞察结构],"questions":[{"text":"结合建议的追问","evidence":[{"id":"ID","quote":"原文摘录"}]}]}。不要输出计数。每段最多200字，overview最多1000字，每个quote最多100字，每项最多2条证据，changes/connections各最多3条，questions最多4条，整个JSON最多12000字符。
```

层级聚合、压缩和结构修复提示词保持不变；月度回顾提示词已改为上面的“建议与追问”版本。

## 代码侧保证

`internal/ai/themes.go`：

- `monthlyThemes`：固定 10 个名称；`ThemeCounts` 只能按这些名称分组，因此分组数 ≤ 10。
- 名称归一化：去空白、全角 ASCII 转半角、常见缺“与”别名映射；例如“AI 与技术”“ＡＩ与技术”都归为“AI与技术”，不会变成新类。
- 每条最多 2 个主题；长原文分片分类后，合并时再去重并截断为 2 个。
- 白名单外的名称先触发一次结构修复；修复后仍不合规，归入“其他”并记录警告，不让整月生成失败。
- 月度结果的 `promptVersion` 从 `3` 升为 `5`（4 = 固定主题，5 = 建议/追问与 gist），旧结果仍可回看。
- 分类输出新增 `gist`（一句话简介，≤60 字）；旧结果没有 gist 时，前端回退为“日期 + 原文前 64 字/首句”。
- 回顾输出新增 `advice`，并兼容旧的 `hypothesis` 字段。

## 前端展示

- **主题分布 → 分类来源**：展开后每个来源直接显示 `日期 · gist`（一句话简介），不需要逐条点开；旧结果没有 gist 时，异步读取原文并显示“日期 + 首句/前 64 字”。点击「查看来源」仍可看全文。
- **关键洞察 / 思考变化 / 可能的联系**：`advice`（旧结果回退 `hypothesis`）显示为「AI 对我的建议」；`limitation` 显示为「适用条件 / 局限」；每条洞察的 `question` 显示为「追问」。
- **顶层问题**：标题改为「结合建议的追问」，问题应从上面的建议派生；重复文本只保留一条。
- 旧结果没有 `advice`/`gist` 时页面仍可正常显示，重新生成后写入新字段。
