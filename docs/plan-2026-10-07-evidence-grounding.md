# Fleeting：真实模型证据落地与可选字段容错（第二轮，基于真实实测）

## 背景：用真实模型实测到的行为（不是推测）

模型 `deepseek-v4-1-flash-260910`，10 月 4–6 日真实内容（1 条 2539 字日整理；2026-10 月 4 条 3748 字洞察）。

- **默认开启思考**：请求体不含任何 thinking 参数，但服务端默认思考（`completion_tokens_details.reasoning_tokens=42`，且返回 `reasoning_content`）。日整理 1 条 2539 字：默认思考 101 秒 / 4 次调用；`reasoning_effort:"none"` 30 秒 / 4 次调用。月洞察：默认思考 22 次调用、737 秒后失败；`none` 后 45–69 秒，失败原因变为证据。
- **`reasoning_effort:none` 与 `thinking:{type:"disabled"}` 在该服务商可用**（reasoning_tokens=0）；`minimal` 无效（50 tokens）；`enable_thinking:false` 被忽略（60 tokens）。
- **真实失败是证据摘录不逐字**：一条 40 字引文仅在「折叠空白」后匹配（原文 2000 字分片内位置 1336）；一条 21 字引文在任何朴素策略下都不匹配（原文长度 1067 → 可能是跨分片引用或模型改写）。当前 `evidence()` 要求 `原始文本.includes(quote)`，任一不匹配即整份月报告失败——这是用户遇到「模型结构校验失败 / 证据校验失败」的直接原因。
- 同一模型的结构性字段本身正常：`question`/`limitation` 都以字符串返回；未观察到多给/少给字段。上一轮的裁剪与围栏解析仍保留。

## 目标

1. 真实模型给出的证据只要**能对应到真实原文**就应当被接受，并**以原文的精确切片存库**（保证「AI 整理，可对照原文」的弹窗永远是原文连续子串）。
2. 个别无法恢复的证据项不能毁掉整份报告：丢弃该证据项；无证据的条目丢弃；只在结果不满足最低质量门槛时才失败。
3. 少给「非核心」散文字段（`hypothesis`/`limitation`/`question`）不应导致整份失败：核心 `fact` 必填，其余可为空并从前端隐藏。
4. 保留上一轮的修复重试、裁剪、围栏解析、截断拆分与 512 次预算，不回归并行/调度/前端隔离。
5. 不改动录入、来源弹窗、补录、导出、登录/CSRF、样式。

## 实现要求

### A. 证据落地（核心）

- `evidence()` 的校验基准改为**该 id 对应的完整原文记录文本**（从本次生成范围内的 entries 取，而不是模型看到的分片文本）。这样同一记录跨 2000 字分片的引用也能成立。
- 匹配失败时按**策略阶梯**尝试定位，命中即把 `quote` 替换为原文中的**精确切片**（保持 `day` 与 id 不变）：
  1. 精确子串；
  2. 折叠所有空白（含换行/多余空格）后匹配，并用索引映射回原文偏移；
  3. 在 (2) 基础上做全角/半角标点归一后再匹配（同样映射回原文偏移）。
  - 实现必须建立「归一化串 → 原文偏移」映射，严禁把规范化文本当结果返回，也严禁在无法映射时返回近似切片。
  - 折叠/归一后仍找不到 → 返回 `null`（丢弃该证据项），不抛错。
- 跨分片引用与同 id 多分片：按 id 取完整原文校验（要求实现中不得用分片文本覆盖完整原文，注意上一轮 `review()` 里的 `allowed` 构造方式需相应调整，确保既能校验分片内也可以校验完整原文）。
- 证据引用必须是本次生成范围内的真实记录 id；未知 id 仍按现有来源校验规则报错（这属于模型编造来源，不静默丢弃）。

### B. 条目级容错与最低门槛

- `insights()`：`fact` 必填且非空；`hypothesis`/`limitation`/`question` 允许缺失或空（存 `""`）。`evidence` 缺失/为空或全部无法落地时，**丢弃该条洞察**（不抛错）。
- `questions`：`text` 必填；证据为空/全部无法落地时丢弃该问题。
- 最低门槛：当范围内记录 ≥2 条时，最终 `insights` 至少 1 条（原为 2）；不足时才失败，错误信息说明「丢弃了无法落地的证据后洞察不足」，不含原文。
- 层级聚合：模型只能引用给定证据，但落地校验仍按 id 的完整原文执行（与 A 一致）；聚合输入里给出的证据切片保持原文精确。
- 以上丢弃/替换必须可诊断（错误信息含阶段与字段路径，不含原文摘录）。

### C. 前端：空字段隐藏

- `web/app.ts` 渲染洞察时跳过空的 `hypothesis`/`limitation`/`question`（保留 `fact` 与证据）；月度/日度类型定义同步为可选。保持现有 class 与布局约束，不新增交互。

### D. 推理档位（已实现，本轮只需落配置与文档核对）

- 已有 `llm.reasoningEffort` / `llm.extraBody` / `LLM_REASONING_EFFORT` / `LLM_EXTRA_BODY`。默认不发送，行为不变。
- README 增加一句实测依据：该服务商默认思考会显著变慢并可导致输出截断，可用 `reasoningEffort:"none"` 关闭（是否支持由服务商决定）；`config.example.json` 加示例注释（不含真实值）。
- **本轮不修改私有配置**（主会话在验收通过后处理）。

### E. 测试（全部 mock、合成文本）

1. 引文含多余换行/空格 → 成功且存库 quote 是原文精确切片（断言 `原文.includes(quote)` 且长度等于原文对应片段）。
2. 引文与原文仅全角/半角标点差异 → 成功且落库为精确切片。
3. 引文跨同一条记录的两个分片 → 成功。
4. 引文完全是改写/不存在 → 该证据项被丢弃；该条洞察若无其他证据则被丢弃；报告仍能成功（同步断言存库数据里不含伪造引文）。
5. 铸造 id 不存在 → 仍按来源错误处理（不被静默丢弃）。
6. `hypothesis`/`limitation`/`question` 缺失或为空 → 成功；前端渲染断言这些行不出现、`fact` 与证据仍在。
7. 记录 ≥2 条但落地后 insights 为 0 → 明确失败且保留旧 ready。
8. 上一轮回归全部保留：裁剪、围栏、结构修复重试、截断拆分、512 上限、并行、调度。
