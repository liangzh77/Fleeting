# Fleeting 首版实施计划（check-run 执行依据）

依据 `docs/product-design.md` 实现可运行的单人自托管 Web 首版，覆盖第一阶段与第二阶段的核心体验。不做第三阶段扩展或装饰性图片生成。项目当前只有文档，允许初始化工程。部署目标：一台有持久磁盘的 Node.js 服务，SQLite；界面中文；时区默认 Asia/Shanghai，可服务端配置。LLM 使用服务端可配置的 OpenAI-compatible endpoint、API key、model；不要求现在有真实 API key。禁止将密钥写进代码、示例或前端。技术栈和目录由执行者选用易维护方案，并在 README 中写明实际选型、运行步骤和限制。

## 必须落地

1. 密码登录单用户、无注册；密码在服务端配置或环境中安全配置（不提交明文），哈希验证，安全的服务端会话 Cookie，登录限速；未鉴权无法读取/修改/导出记录或生成 AI。提供初次设置密码说明。浏览器不接收密钥；写接口有 CSRF/Origin 保护；公网使用 HTTPS 的要求在 README 写明。
2. 简洁的响应式中文 Web 界面：竖屏单列，宽屏舒适写作区；登录后首页直接输入，完成后保存服务端时间和原文、清空后可继续写；保存失败保留输入，避免重复提交。今日记录可见。基本无障碍（标签、焦点、键盘、触摸区域）。
3. 按配置时区确定本地日期，按天查看原文（粗时间线），提供修改、删除；能按天回看，最好有搜索。数据持久化于 SQLite，附备份/导出 JSON 或 Markdown 的方法/API；原文不被 AI 覆盖。删除/修改后相关结果不再被当成最新有效结果。
4. 对选定日期手动「总结」，使用当日全部原文按时间排列、要求保真不编造，包含时间段及可回查的来源；独立存储结果。未配置模型或模型调用失败时普通记录仍正常使用，并给出明确状态。当天记录改变后日总结标记过期，用户可重新生成。
5. 对选定月份手动生成图文月度回顾：至少有主题分布图（数字根据可追溯的结构化分类/来源计算，不凭模型猜计数）、思考变化/联系、开放问题和 2–4 条带日期及原文证据的洞察；明确区分事实与推测，材料不足不强行结论。记录变化后报告标记过期。无需真图片生成或聊天功能。
6. 保护隐私：只有手动生成才发送原文到所配置服务商；UI 在首次使用 AI 功能时说明；禁将原文/密钥记入日志；模型返回的内容安全渲染；所有端点鉴权，不将用户文字当指令执行。配置示例、.gitignore、README。
7. 自动化测试覆盖记录/日归档与午夜边界、登录保护、保存与重复提交、派生结果过期、AI 缺配置/错误分支、月报告数值口径；说明并实际执行 typecheck、测试、构建；无法运行的明确注明。若需要外部模型验收，使用 mock 测试，不能捏造真实服务验证。

## 边界与验收

- 目标是可运行、真实持久化、完整贯通的首版，而非静态 mock 页面。可用单一 Node 服务同时提供 API 与前端；不依赖尚未给出的密钥。
- 在没有密钥时 AI 生成操作明确不可用，不能假装已生成报告。
- 避免先造复杂队列、向量库、多用户/注册、自动云部署、心理诊断、游戏化。
- 文档中区分已实现与未来建议。不要改动 `docs/product-design.md` 中原始产品意图，除非为澄清事实作必要小改。
- 交付工作区中的源码、运行和测试说明，记录实际命令与结果；验收模型必须独立看代码和测试，不以执行者自述为准。
