# Fleeting · 随笔

单人自托管的中文随笔应用：打开即写，按天回看；手动日整理与月度回顾。原文与 AI 结果独立保存。

## 实际选型

- Node.js **22.13+（建议 22.23+）**、TypeScript、Express 5；一个服务同时提供 API 和静态前端。
- SQLite 使用 Node 内置 `node:sqlite`（Node 22 仍会提示 ExperimentalWarning），WAL、单实例、持久磁盘。
- 前端原生 TypeScript + esbuild，无前端框架、第三方分析或 CDN。所有文字以 DOM `textContent` 渲染，不执行 HTML / Markdown。
- 密码 scrypt 哈希；服务端 SQLite 会话（浏览器仅持有随机令牌，库中保存令牌 SHA-256），7 天到期；CSRF 令牌 + 严格 Origin 校验。

## 本机开始

```sh
npm ci
npm run password          # 可选：终端交互设置密码；也可按下方说明直接编辑 config.local.json
npm run build
npm start
```

打开 **http://localhost:3000**。不要换成 127.0.0.1 访问，除非同步修改配置中的 `origin`。默认绑定 `127.0.0.1:3000`。`npm run dev` 会先构建再以 tsx 启动，**不提供热更新**。

- 密码允许 1–1024 个字符，不接受空密码或命令行明文参数。短密码容易被猜中，尤其是公网部署时，强烈建议设置较长的随机密码。也可以直接在私有 `config.local.json` 中写 `"password": "你的新密码"`（可与已有 `passwordHash` 同时存在，优先使用新的 password）。**重启时**服务会在开始监听之前将其哈希化写入 `passwordHash`，并删除明文 `password` 字段；不会把明文长期保留。若密码不合要求或写入失败，服务拒绝启动。仅用可信编辑器修改该文件，权限设为 0600；编辑器的历史/云同步及备份也可能保留曾输入的明文。
- 忘记密码：停止服务，在 `config.local.json` 里写新 `password`，或运行 `npm run password`，再启动。检测到哈希改变后撤销所有旧会话。`npm run password` 也会删除待迁移的 `password`。环境变量 `PASSWORD_HASH` 若已设置会覆盖文件中的哈希，使用配置文件的明文重设前需移除该变量。
- 可以参考 `config.example.json`；`config.local.json`、数据库、`.env`、构建产物已忽略。**不内置任何可登录密码或模型凭据**。
- 如使用私有配置文件，`FLEETING_CONFIG=/绝对路径/config.json`。应用不会自动读取 `.env`，用服务管理器注入环境变量。

配置与环境变量（环境优先）：

| 配置字段     | 环境变量      | 含义                                                 |
| ------------ | ------------- | ---------------------------------------------------- |
| origin       | APP_ORIGIN    | 精确的浏览器 origin，无尾斜杠、无路径                |
| timezone     | APP_TIMEZONE  | IANA 时区，默认 Asia/Shanghai                        |
| database     | DATABASE_PATH | 默认 ./data/fleeting.sqlite                          |
| password     | —             | 配置文件中一次性输入明文新密码，重启时转为哈希并移除 |
| passwordHash | PASSWORD_HASH | `scrypt:盐:哈希`；可用本机命令生成                   |
| llm.baseUrl  | LLM_BASE_URL  | OpenAI-compatible 基础地址，通常以 /v1 结尾          |
| llm.apiKey   | LLM_API_KEY   | 服务端私有密钥                                       |
| llm.model    | LLM_MODEL     | 服务商实际支持的模型名称                             |
| llm.reasoningEffort | LLM_REASONING_EFFORT | 可选，发送为 reasoning_effort，空字符串不发送 |
| llm.extraBody | LLM_EXTRA_BODY | 可选 JSON 字符串，最多 2000 字符；非法配置启动报错 |
| —            | PORT / HOST   | 监听端口 / 地址                                      |

数据库第一次打开时固定归档时区；后续换时区会拒绝启动，避免旧日期与新日期混用。时间存 UTC，日归属按配置时区计算，不按浏览器或服务器本地时区。编辑保持原始记录时间及日归属。

## 公网部署与隐私

**公网必须 HTTPS**，设置如 `APP_ORIGIN=https://notes.example.org`，反向代理到本机端口。应用可挂在站点根路径，也可挂在子路径（如 `https://example.org/fleeting/`）：此时代理用 `handle_path` 剥掉前缀，且必须把目录式 URL（`/fleeting`）跳转到带末尾斜杠的形式。非本机 HTTP origin 会拒绝启动。HTTPS 模式使用 `__Host-`、Secure、HttpOnly、SameSite=Strict Cookie，配置 HSTS、CSP、禁止 iframe。代理必须删除外部可伪造的请求头，不要缓存 API/页面，限制请求大小和连接数；不要记录请求正文、Cookie、Authorization 或模型响应。

服务只信任回环代理（如 Caddy）附加的 `X-Forwarded-For`：直连客户端无法伪造，反向代理下登录限速按真实客户端地址分桶（30 秒最多 8 次尝试），一台代理加多个访客不会互相牵连。建议代理额外做连接限速。成功登录也计入限额。密码修改需重启。不要通过反向代理暴露多个 Node 实例：生成锁是单实例设计。

本仓库的 `deploy/` 目录包含生产部署材料：`bootstrap.sh`（服务器初始化：Node 运行时、服务账号、目录、systemd、每日备份）、`deploy.sh`（本地构建 + 上传 + 重启 + 探活）、`fleeting.service`、`backup.mjs`、`caddy-private.snippet`，说明见 `deploy/README.md`。参考实现部署在 `https://liangz77.cn/fleeting/`：Caddy 用 `handle_path` 把 `/fleeting/*` 交给应用（剥掉前缀），前端因此把资源引用写成相对路径、接口前缀由页面地址推导，同一份构建既能挂在根路径也能挂在子路径下；旧地址 `/private` 永久跳转到新地址。

生产进程应以独立非 root 用户运行，使用 `umask 077`，私有配置 `chmod 600`、数据/备份目录 `chmod 700`，磁盘加密及严格主机访问权限由部署者承担。SQLite、备份和导出均是未加密的私人数据，不放到静态目录。运行目录保持项目根目录（静态文件从 `public/` 提供）。

所有记录、搜索、导出、结果和生成接口必须登录；写操作同时检查 Origin 和会话 CSRF。只有登录页和静态资源公开。浏览器从不接收模型密钥。应用日志只记录启动信息，不记录原文或原始错误；没有第三方跟踪。

**每天按配置 `timezone` 的 01:00 自动向配置的模型服务发送昨天的私人原文进行日整理，服务需运行**。离线错过时，当天 01:00 后启动可补做昨天，不追溯更早日期；未配置模型、无记录或已有相同来源的成功结果跳过。自动尝试持久化，每天最多一次，失败保留原文和旧结果，可手动重试。手动整理仍须点击并确认。首次 AI 操作有隐私提示（每次重新登录重新确认）；自托管不等于不出服务器。服务商如何保存输入由其政策决定。没有配置模型时仍可记录、编辑、回看、搜索、导出，AI 明确不可用。

## 已实现的体验

- 中文响应式随笔（写作与按天浏览合并）、洞察两个页面；当前页的导航按钮有醒目的选中状态（`aria-current="page"`），退出按钮不表示页面。手机竖版标题与「随笔 / 洞察 / 退出」同一行。输入区、当日整理、原始记录依次排列；浏览旧日期时新增记录仍按服务端当前日期时间保存，并返回今天。今天/回看记录采用紧凑列表，点击记录选中后，通过列表标题右侧唯一的「修改 / 删除」入口操作。密码登录，无注册。完成保存后清空并保留焦点；Cmd/Ctrl+Enter 保存，普通 Enter 换行。
- 服务端时间、原文保留、SQLite 持久化；保存幂等标识，丢响应重试不重复；失败输入保留。未确认上次保存时继续编辑会保留为独立草稿；「确认上次保存」先用旧幂等标识重试旧内容，新草稿不清空，需再次点击完成保存，避免网络歧义产生重复记录。页面内存草稿随导航保留，**刷新/关闭会丢失**，不往 localStorage 写私人文字。
- 今日记录（进入首页、恢复可见/焦点及每分钟向服务端校准日期，跨午夜保留草稿）、选日期、已有记录日期列表、精确子串搜索（最多 200 条）、版本冲突保护、编辑、永久删除确认、全部 JSON / 当日 Markdown 导出。
- 手动日整理：当日全部原文按时间排序；段落按来源顺序排列，粗时间段由服务端依据来源时间计算，区别于事件发生时间；每块最多 4000 字符，长单条按 2000 字符片段完整拆分，保留同一来源及时间；截断自动拆半重试；每块生成后再次用原文核对细节与无依据增补；去口录重复与填充词但保留具体细节；每个短句 / 小段正文可点击查看全部关联原文，来源已删除时显示「原文已删除」。校验分段来源合法且覆盖全部记录，兼容旧版段落级来源。模型核对不是“不丢信息”的数学保证，必须对照原文。
- 手动月报告：以全部原文分块抽取信息点和多标签分类；每个片段先生成带精确证据的回顾，再层级归纳全部回顾和证据，不无限传全部原文；阶段概括、主题条形图、事实/推测分离的 2–4 条洞察、思考变化、可能联系、开放问题与日期/原文证据。仅一条记录时洞察可少于 2 条，明确材料不足。
- 图表由程序按结构化分类的**唯一记录 ID**计数；一条多标签，合计不必 100%。分类覆盖全部来源，证据摘录必须是原文子串，日期从数据库填充，不相信模型的日期/数字。可逐类查看来源，但首版尚不支持纠正分类。
- 来源版本、模型、提示词版本、生成时间持久化，已有结果可直接回看，不自动再生成。同一类型和范围只允许一个 AI 任务，不同范围可并行，生成中可继续记录；结果状态可轮询，服务重启将未完成任务标为失败。
- 新增/修改/删除后已有日/月整理内容不变，读时按来源快照判定过期并提示新增/修改或删除。最近任务状态与最近成功内容分开返回；重新生成期间及失败后仍显示旧内容，成功才替换。生成期间原文变化时，成功内容仍保存并提示过期。**删除原文不会清除已有整理里的派生文字**，只有用户再次生成才更新当前展示；历史成功结果仍保存在数据库。原文从不被 AI 覆盖。

## AI 接口与限制

配置 `baseUrl/apiKey/model` 三项即启用。模型需支持 `POST /chat/completions`、`response_format: {type: "json_object"}` 和 `max_tokens`（上限 8192）；不支持该协议的服务会明确失败。每次调用 90 秒超时；长范围需多次调用，前端等待时间可能较长，代理须允许较长请求。生成无工具权限，提示词声明原文是资料而非指令；模型输出经过结构/来源/摘录校验，最终按固定 DOM 组件纯文本显示。**提示词与校验不能保证语义完全真实或完全抵抗模型误解**。

真实实测中，该服务商默认思考显著变慢并可能导致输出截断，可用 `reasoningEffort:"none"` 关闭（是否支持由服务商决定）。Fleeting 默认不发送任何 thinking / reasoning 参数，推理耗时由服务商默认决定；想试关闭推理，可按服务商选择 `reasoningEffort`（例如 `"none"`）或 `extraBody`（JSON 字符串，例如 `"{\"thinking\":{\"type\":\"disabled\"}}"` 或 `"{\"enable_thinking\":false}"`），不保证服务商支持。环境变量覆盖文件配置（空字符串可清除）；合并顺序为程序字段 → `reasoning_effort` → `extraBody`，后者禁止覆盖 `model/messages/stream/tools/tool_choice/response_format/max_tokens/max_completion_tokens` 及原型相关键，冲突启动报错；示例文件的 `_reasoningExamples` 仅为说明，不发送。

模型数组超出字段软上限保留前 N 项（主题 5、洞察 4、变化/联系 6、问题 4），文本超长按字段上限安全截断；非数组、超过 2000 项、必填空白、来源/证据无效仍失败，不捏造默认值、不静默丢弃无证据洞察。各阶段结构错误最多修复一次，把该次输出与资料送回同一模型；修复计入全局预算，仍失败保留旧成功结果。重新部署后，已失败月份直接点「重新生成」，无需删除旧结果。

首版限制每条 8000 字符、单次范围 500 条 / 12 万字符，超限在发送前拒绝。日整理按块核对；月度采用有界分类与层级归纳；每任务最多 512 次调用，单个请求材料最多 60000 字符，128 字符及以下不再拆分，单个中间月回顾最多 12000 字符。自动拆分和压缩重试仍无法完成时明确失败，**不会截掉输入原文或保存未通过校验的结果**。主题跨块命名可能有歧义；模型可误分类，不把记录频率当成生活占比。洞察数量约束不应视为真实语义质量已验证。

首版不做：注册、多用户、复杂队列、离线同步、自定义日期范围/周报告、云部署、图片生成、聊天、心理评分、人格诊断、分类纠正、删除撤销。仅提供月度范围。真实服务商尚未验收：自动化 AI 测试使用 mock，不含真实 key。

## 按日期补录旧日记

如果只知道写作日期、不知道具体时刻，可在**本机终端**补录原文，不需要编造时间。先把原文放在权限为 0600 的私有文本文件中，然后运行：

```sh
npm run import:entry -- 2026-10-04 /私有路径/原文.txt
```

也可把内容通过标准输入传入，最后的换行不会计入正文：`npm run import:entry -- 2026-10-04 -`。脚本按日期归档；`createdAt` 记录实际**补录时间**，`timeUnknown=1` 表示旧日记的具体时间未提供。回看、Markdown 导出和 AI 日整理会显示「补录 · 时间未记录」，不会把补录时间误认为当天记录时间；原文内容不变。重复导入同一天完全相同的文字不会生成第二条。单条最多 8000 字；已有日/月 AI 结果会标记过期。

## 导出、备份与恢复

登录后 UI 可以下载全部 JSON、当日 Markdown。接口：

- `GET /api/export`：格式版本、时区、导出时间和全部原文及版本。
- `GET /api/export?day=2026-10-07&format=markdown`：按日可读文本（正文保留原样，在其他 Markdown 阅读器打开时应禁用 HTML）。
- 导出是迁移材料，不包括会话/AI 结果；首版无批量导入 UI。

一致性备份（调用 SQLite online backup，不直接复制活跃 WAL 数据库）：

```sh
npm run backup -- /私有备份目录/fleeting-日期.sqlite
```

目标必须不存在，备份权限 0600。备份包含原文、派生元信息和会话；也需备份私有配置，但不要放在仓库。可在服务运行时备份；示例脚本**不会自动安排备份或清理**。

恢复步骤：

1. 停止 Node 服务；备份当前数据库供回滚。
2. 删除旧数据库旁的 `-wal` / `-shm`（只在服务已停止后），用备份替换 `DATABASE_PATH` 指向的主文件，检查文件权限。
3. 如备份来源不完全可信或希望撤销其会话，重设密码，再启动服务。
4. 登录检查日期/条数，导出 JSON 核对。测试实际执行了 online backup → 打开恢复副本 → 核对原文。

建议至少每日备份，自己设置保留期并定期验证恢复。删除主库原文并不会删除历史备份、已下载的导出或服务商留存。SQLite WAL/空闲页也可能包含旧字节，文件级彻底擦除不作保证；对严格隐私要求使用加密磁盘和受控备份生命周期。
